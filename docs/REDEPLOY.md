# 换台机器重新部署（照做即可）

从零把 OCIBot 装到一台新服务器，并把原来的租户搬过去。全程复制粘贴，不需要理解每一步。

**预计 20 分钟**，其中等证书签发约 1 分钟。

---

## 你需要准备

- 新服务器一台（Ubuntu / Debian / Oracle Linux 都行），能 SSH 登录
- 一个域名（可选，但强烈建议——没有域名就只能用 IP + 明文 HTTP）
- 旧面板还能打开（用来导出备份）

---

# 第一部分：在**旧机器**上导出（3 分钟）

> 已经没有旧机器 / 是全新安装，跳到第二部分。

## 1.1 导出租户备份

1. 打开旧面板 → 左侧 **备份**
2. 设一个**备份密码**（自己想一个，记牢，等下要用）
3. 点导出，浏览器会下载一个 `.zip` 文件
4. **把这个 zip 存到你自己的电脑上**

这个 zip 里是加密的租户配置和 OCI 私钥。丢了密码就解不开，没有找回途径。

## 1.2 记下这些信息

| 项目 | 在哪看 |
|------|--------|
| 你的登录用户名 | 面板右上角 |
| 备份密码 | 刚才自己设的 |
| 域名 | 你现在访问面板用的那个 |

> **不需要**把旧机器的 `web/.env` 搬过去。新机器会生成自己的密钥，
> 导入 zip 时会用新密钥重新加密。少一件容易搞错的事。

## 1.3 需要另外记下来的（备份不含）

加密备份**只包含租户**。下面这些在新机器上要重建，现在去旧面板看一眼截个图：

- 定时开关机任务（任务中心）
- 通知渠道（Telegram / Bark 等的配置）
- 正在跑的抢机任务

---

# 第二部分：在**新机器**上安装（10 分钟）

## 2.1 装 Docker

SSH 登录新服务器，逐条执行：

```bash
curl -fsSL https://get.docker.com | sh
```

```bash
docker --version
```

第二条能打印出版本号就算成功。

## 2.2 装面板

```bash
export OCIBOT_REPO_URL="https://github.com/674542449/ocibot.git"
export OCIBOT_BRANCH=main
curl -fsSL https://raw.githubusercontent.com/674542449/ocibot/main/scripts/install.sh | bash
```

等它跑完（首次要构建镜像，约 3–5 分钟）。结尾出现 `就绪：http://127.0.0.1:8000` 即成功。

## 2.3 开放端口（**Oracle 云必做**）

Oracle 云的实例默认只放行 22 端口，网页打不开、证书也签不了。两处都要开：

**① OCI 控制台**：实例 → 子网 → 安全列表 → 添加入站规则，
放行 **TCP 80、443**（源 `0.0.0.0/0`）。

**② 实例内防火墙**：

```bash
sudo iptables -I INPUT 1 -p tcp -m multiport --dports 80,443 -j ACCEPT
sudo netfilter-persistent save 2>/dev/null || sudo iptables-save > /etc/iptables/rules.v4
```

> 其他云厂商（腾讯云 / 阿里云 / Vultr 等）只需在控制台安全组放行 80、443。

## 2.4 注册账号

浏览器打开 `http://新服务器IP:8000`

**注册第一个账号 —— 它自动成为管理员。**（之后注册就关闭了，不用担心别人来注册。）

建议用和旧机器相同的用户名，方便对照。

## 2.5 导入租户

面板左侧 **备份** → 选择你下载的那个 zip → 填**备份密码** → 导入。

导入完去 **租户** 页看一眼，原来的账号都应该在。

# 第三部分：配域名 + HTTPS（5 分钟）

## 3.1 改 DNS

去域名商后台，把域名的 **A 记录**指向**新服务器的 IP**。

等 2–5 分钟生效，然后在新服务器上验证：

```bash
dig +short 你的域名
```

必须输出新服务器的 IP。**不对就别往下走**，证书一定签发失败。

## 3.2 一键配置

```bash
cd ~/ocibot && bash scripts/setup-proxy.sh 你的域名
```

它会自动装好反代、改好所有安全配置、重启并自检。没装过 Nginx Proxy Manager 的话它会问你要不要装，回车即可。

跑完会打印一段「在 NPM 里填什么」，**照着填**。

## 3.3 在 NPM 网页里填表

按脚本打印的值填就行。三个容易踩的点：

- **Forward Hostname 填容器名**（`ocibot-api-1`），不是 IP
- **Websockets Support 必须打开** —— 不开的话只有网页终端连不上，其余全正常，很容易误判成终端有 bug
- **Advanced 标签页**粘一行 `client_max_body_size 50m;` —— 不加的话备份导入和上传会以看不懂的方式失败

---

# 第四部分：完工检查（4 条）

```bash
dig +short 你的域名
```
→ 输出新服务器 IP

```bash
curl -m 5 http://新服务器IP:8000/api/health
```
→ **必须超时或被拒绝**。能通说明明文端口还暴露在公网上，回去看 `setup-proxy.sh` 的输出

```bash
curl -sI https://你的域名 | grep -i strict-transport
```
→ 有输出，说明 HTTPS 相关配置全部生效

**浏览器里**：登录 → 打开任意实例的「网页终端」→ 能出命令行提示符 = Websockets 正常

# 第五部分：收尾（别跳过）

## 5.1 备份新机器的密钥

```bash
cat ~/ocibot/web/.env
```

**把输出整段存到密码管理器**。里面的 `OCIBOT_MASTER_KEY` 是解密所有 OCI 私钥的钥匙，
文件丢了就只能重新导入租户。

## 5.2 重建旧机器上的任务

对着第 1.3 步的截图，把定时任务、通知渠道重新建一遍。

## 5.3 GitHub 账号开 2FA

面板的「一键更新」是从你的 GitHub 仓库拉代码后在这台服务器上执行的。
**GitHub 账号被盗 = 这台服务器被拿下**，这是整套部署里最短的一条攻击路径。

## 5.4 旧机器

确认新机器一切正常后再动旧的。彻底不要了就：

```bash
cd ~/ocibot && OCIBOT_PURGE_DATA=1 ./scripts/install.sh uninstall
```

> 这会**删除数据库卷**，旧面板的数据就没了。确认新机器没问题再执行。

# 出问题查这里

| 现象 | 原因 / 处理 |
|------|------------|
| 网页打不开、证书签发失败 | 80/443 没开放。回到 **2.3**，OCI 的两处都要做 |
| `dig` 输出的 IP 不对 | DNS 还没生效，等几分钟；或 A 记录填错了 |
| NPM 显示 502 | Forward Hostname 填成了 `127.0.0.1`。改成 `ocibot-api-1` |
| 网页终端连不上，其他都正常 | NPM 的 **Websockets Support** 没开 |
| 登录后立刻被登出 | 用 `http://` 访问了。NPM 里 Force SSL 打开，用 `https://` |
| 导入备份报密码错误 | 备份密码不对；或 zip 传输损坏，重新下载一次 |
| 备份导入 / 上传失败 | Advanced 里没加 `client_max_body_size 50m;` |
| 安装脚本卡在构建 | 内存不足。1GB 内存的小机器建议先加 swap |

还是不行的话，把执行的命令和完整报错贴出来问，不用自己判断是哪一步的问题。
